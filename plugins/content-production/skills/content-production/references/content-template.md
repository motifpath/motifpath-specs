# Content production packet

Copy and fill this template for each language-specific unit. This is an editorial artifact,
not an API payload. Replace prompts with concrete content; mark unknowns and their impact.

## PDCA cycle record

- Unit/batch key; cycle number; current phase; content version; packet version.
- Requested scope: selected phase or cycle; inputs and prior packet/version.
- Plan: outcome, acceptance criteria, observation method, baseline or unknown.
- Do: draft/assets produced and changes from the brief.
- Check: exact revision reviewed, evidence, findings/severity, reviewer type,
  pass / revise / blocked verdict, pending human/runtime checks.
- Act: revise / retain / propose release / retire, rationale, evidence limitations,
  change log, unresolved findings and next phase.
- Publication approval and delivery status recorded separately.

## Identity and source evidence

- Working key/title; version/date; author/reviewer; status: draft / review / ready.
- Learner and use context; instrument(s); language/locale; difficulty.
- Source repository revision and reviewed source paths/sections.
- Existing related content and why this unit is needed.
- Curriculum participation: yes/no. If yes: track/course/path/lesson keys, principles,
  position, assumptions and closing application; alignment deviations for review.
  If no: record standalone explicitly and skip placement fields.

Difficulty: beginner / early_intermediate / intermediate / advanced / expert.
Explain the classification through the actual attempt; list curator gaps instead of inventing keys.

## Learning promise

- By the end, the learner can: one observable action in a musical context.
- Why it matters now: concrete payoff, including the purpose of each exercise element.
- Dedicated opening application slide/section: actual learner-facing copy, immediate-use
  example, later subjects supported and the specific connection to each.
- Assumed knowledge: each prerequisite, a quick check, exact reference/section and an
  inline bridge or alternative if needed. State language/access requirements.
- Estimated time and what is deliberately outside this narrow outcome.

## Learner-facing sequence (write fully in the target language)

| Beat | Actual learner-facing copy and asset | Learner action | Value and success/feedback |
|---|---|---|---|
| Application opening | Dedicated slide/section with use now and future-subject connections | Recognize a musical use | Concrete relevance before explanation |
| Hear/see the payoff | Practical musical example | Notice a specific feature | Why this matters |
| Get the method | Complete steps and annotated demonstration | Follow the method | No hidden step |
| Try it | Concrete task with stimulus and response | Listen/select/tap/play | Answer/rubric and rationale |
| Correct and retry | Common error and focused correction | Change one thing and repeat | Observable improvement |
| Apply | Phrase, groove, lick or repertoire fragment | Use the skill in music | Success check |
| Continue | Useful practice instruction and references | Repeat with variation | Today's payoff already delivered |

These are learning beats, not a fixed slide count. Keep the application opening as its own
slide in slide-based drafts; other beats may merge when clear.
Use the [draft review guidelines](draft-review-guidelines.md) to review the syllabus,
transitions, visible diagrams, practice wording and exact supporting-resource map.
Feedback may follow an attempt; this is pedagogical timing, not withholding a technique.

For each teaching step, record the knowledge the learner brings, the new idea, the next
action and what that action demonstrates. Trace those actions back to the observable
outcome. State what support the learner uses, such as a labelled diagram.

| Assessed outcome | Guided practice, retry or application | Likely mistake and targeted feedback | Fresh example and evidence |
|---|---|---|---|
| Observable action | Activity key and available support | Explain the correction the learner can apply | Test the same reasoning with a different example and state what the response demonstrates |

Use a follow-up where the learner can apply the correction. Choose an appropriate task
or rubric for open-ended practice.

## Observe and revise

Name the observable learning check, available events or manual observation, baseline if known,
and what would trigger revision. No invented targets. Separate lesson completion, practice
accuracy, fluency and retention. For a proposed skill or principle change, fill in the Act record below and route it for review.

| Observed problem | Evidence type and source | Proposed reusable rule | Worked example | Check in the next lesson |
|---|---|---|---|---|
| Name the problem and where it occurred | Editorial judgment, learner observation or verified platform behavior | State the conditions where the rule applies | Show how the rule changes a lesson | Describe what a reviewer should observe |

Use the same review route for proposed curriculum plan changes.
